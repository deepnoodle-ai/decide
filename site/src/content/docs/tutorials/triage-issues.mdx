An issue that says "checkout is slow" can't be started until someone asks
what it means. Here you label those issues as they arrive.

You need decide [installed](/start/#install-decide), an
[API key](/start/#get-a-key), and a GitHub repository where you can add a
workflow.

## Get the demo

decide's repository has six sample issues, some clear and some vague:

```sh
git clone --depth 1 https://github.com/deepnoodle-ai/decide
cd decide/demo
```

## Judge the issues

`task-readiness` asks whether an issue is ready to start, and how large it
is. Run it on the six issues, then show the three nearest a flag:

<Terminal tape="triage-run" title="~/decide/demo" label="decide flags issues 102, 104 and 106 as not ready">
**Three of six issues are flagged as not ready.** Each says what is wrong
but not what to change, or how to tell when it's done.
</Terminal>

## Add the workflow

Add your key as a repository secret named `TYPESAFE_API_KEY`, and create
a `not-ready` label. Then save this as `.github/workflows/triage.yml`:

```yaml title=".github/workflows/triage.yml" collapse={15-21}
name: triage

on:
  issues:
    types: [opened]

permissions:
  issues: write

jobs:
  readiness:
    runs-on: ubuntu-latest
    steps:
      - name: Install decide
        run: |
          base=https://github.com/deepnoodle-ai/decide/releases/latest/download
          curl -fsSLO "$base/decide_linux_amd64.tar.gz"
          curl -fsSLO "$base/checksums.txt"
          sha256sum --check --ignore-missing checksums.txt
          tar -xzf decide_linux_amd64.tar.gz decide
          sudo mv decide /usr/local/bin/

      - name: Label the issue if it isn't ready
        env:
          TYPESAFE_API_KEY: ${{ secrets.TYPESAFE_API_KEY }}
          GH_TOKEN: ${{ github.token }}
          TITLE: ${{ github.event.issue.title }}
          BODY: ${{ github.event.issue.body }}
          NUMBER: ${{ github.event.issue.number }}
        run: |
          status=0
          printf '%s\n\n%s\n' "$TITLE" "$BODY" |
            decide run task-readiness --each file --fail-on flagged ||
            status=$?
          if [ "$status" -eq 2 ]; then
            gh issue edit "$NUMBER" --repo "$GITHUB_REPOSITORY" --add-label not-ready
          elif [ "$status" -ne 0 ]; then
            exit "$status"
          fi
```

Keep the issue's text in `env`, as above. Written into the script as
`${{ github.event.issue.body }}`, an issue's text could run commands.

Each new issue is one request on your key.

## Check that it works

Run the workflow's command on a vague issue, and print the exit code:

<Terminal tape="triage-check" title="~/decide/demo" label="decide flags the vague issue as not ready and exits with code 2">
**The issue is flagged, and decide exits with code 2**, so the workflow
adds the label.
</Terminal>
