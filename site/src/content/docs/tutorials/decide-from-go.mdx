An agent proposes a file operation. You need a decision about whether to
allow it, ask a person to review it, or escalate because the request is
unclear. The model answers a typed question; your Go policy makes that
decision.

<Goal answer="action  allow / review / escalate" tone="neutral">
<Fragment slot="end">
A runnable Go program that prints a policy outcome and its reason. It
evaluates a proposed action without executing it.
</Fragment>
<Fragment slot="need">
- Go 1.27 or later
- A TypeSafe key set as `TYPESAFE_API_KEY`: [get one](/start/#get-a-key)

<Steps>

1. ## Create a module

   ```sh
   mkdir gate && cd gate
   go mod init example.com/gate
   go get github.com/deepnoodle-ai/decide
   ```

2. ## Ask what the user requested

   Save this as `main.go`. It is the repository's runnable `gate` example,
   included directly so the tutorial and the compiled program stay in step:

   <Code code={gate} lang="go" title="main.go" meta={`collapse={1-${gate.split('\n').length}}`} />

   `decide.Choice` offers three named options. `none` means the requested
   action is unclear or the proposed operation does not match it. It is a
   real answer, so the policy can escalate it rather than guessing.

   The model sees the user's words and the proposed call together. The
   `context.Context` travels with the network request. If the request fails,
   a missing response escalates instead of allowing the operation.

3. ## Read the policy

   The example sets `Measure: gate.MeasureConfidence`, so `gate.Asymmetric`
   uses the API's reported **confidence**, from 0 to 1. This is a separate
   field from the chosen option's probability; the policy compares
   confidence against these thresholds:

   | Chosen option | Outcome |
   | --- | --- |
   | `read_file` | allow at confidence 0.60 or more; below that, escalate |
   | `delete_file` | allow at confidence 0.85 or more; review from 0.60 to below 0.85; otherwise escalate |
   | `none` | always escalate |

   These thresholds demonstrate a policy; they are not measured safety
   guarantees. Use labeled examples from your own traffic to choose them,
   and check them on held-out examples. A model's answer does not grant
   permission: apply your application's authorization checks too.

4. ## Run it

   This program's `decide.NewClient` reads `TYPESAFE_API_KEY` and uses Jev.
   For Cloudflare or OpenAI, first replace that client construction with
   [backend.NewClient](https://pkg.go.dev/github.com/deepnoodle-ai/decide/backend)
   configured for your provider. Setting `DECIDE_PROVIDER` alone does not
   change the root Go client's provider.

   <Terminal tape="go-gate" title="~/gate" label="The Go gate example prints an outcome and its reason">
   The program prints **allow**, **review**, or **escalate**, followed by
   the reason. The request to “clean up the drafts” is ambiguous, so your
   model may decline to choose a file operation. The exact outcome can vary.
   </Terminal>

   Change the request to a clear instruction such as “Show me the contents
   of drafts/final.txt,” and change the proposed operation to `read_file`.
   Run it again. The policy stays in your code while the model answers the
   new question.

</Steps>

## Put it in your application

The example stops at printing the decision. Your application decides what
each outcome does, such as queueing a review, requesting clarification, or
calling an authorized operation. Keep those actions separate from model
output, and preserve the response and policy reason when you need evidence.

Use [decidetest](https://pkg.go.dev/github.com/deepnoodle-ai/decide/decidetest)
to test each outcome and failures without a live provider.
