A model can point to a suspicious function without proving there is a bug.
Here decide ranks where to look, and Claude reads each candidate before it
reports a finding.

You need decide [installed](/start/#install-decide), an
[API key](/start/#get-a-key), [jq](https://jqlang.org/), and Claude Code
with the [decide plugin](/reference/claude-code/#in-three-steps).

## Get the demo

The demo's shop repository has six planted security bugs, beside safe
versions of the same operations:

```sh
git clone --depth 1 https://github.com/deepnoodle-ai/decide
sh decide/demo/setup.sh shop && cd shop
```

## See where to look

Run `security` on the admin functions, then list the six nearest a flag:

<Terminal tape="security-rank" title="~/shop" label="A security run followed by the top six candidates, including Server.ExportOrders">
**`Server.ExportOrders` is a candidate for command injection.** Its
position may differ on another run.
</Terminal>

## Ask Claude to confirm

Start Claude Code in `shop`, and run the plugin's audit skill:

```text
/decide:audit admin
```

Claude reads up to 15 candidates with their callers, and gives each a
verdict:

- **Confirmed:** untrusted input reaches an operation that does harm.
- **Suspected:** Claude can't tell whether it does.
- **Dismissed:** the code prevents it.

## Follow one finding to its source

This is the demo's `Server.ExportOrders`:

The request's `folder` value goes into a string sent to `sh -c`, so a `;`
in it starts another command.

## Use it on your repository

Run `/decide:audit` in your own repository. Your source code goes to your
provider, so choose a scope you can share with it.

The template asks about injection, SSRF, XSS, weak cryptography, and
disabled TLS verification. It doesn't cover path traversal, authorization,
or deserialization.
